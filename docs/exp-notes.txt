Open loop vs close loop
=======================
Close loop: bounded queue length by construction. More stable system & more confidential results. With open loop need to a. have some "burning" stage(s) in the loop to actively (and arbitrarily) bound inflight workload and b. use bounded queues everywhere else to correctly back pressure the burning stages. optionally c. monitor queues and identify the ones that indeed back pressuring. may cause suboptimal performance by scheduling.

Open loop: bounded number of client/connection, desirable for heavily batched systems that requires a LOT of concurrent requests to saturate. If with close loop, the number of client has to be on par with the concurrency, and colocate too many clients on the same machine to be practical.

Choose open loop if can only choose it. No canonical "reply". Send happens at predefined instants e.g. following some traces.


QUIC vs TCP
===========
QUIC (quinn) adds noticeable overhead, but seems sensible for bringing point to point secure.

QUIC allows connect before listen. Simplifying interconnecting routine.

QUIC support (encourage maybe?) ephemeral single message (unidirectional) stream. Not only potentially better performance (despite out of order message delivery which does not matter for distributed protocols) but also easier to program. TCP stream reader either explicitly framing or relying on self-delimited encoding schemas.

QUIC allows overloading same 4-tuple by multiple connections.
